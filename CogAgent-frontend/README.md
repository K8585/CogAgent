# CogAgent 控制台（前端）

CogAgent 企业级 AI Agent 平台的 Web 控制台。用 Vue 3 + Vite 构建，对接 `CogAgent-trigger` 模块暴露的三个 HTTP 接口。

界面围绕「**一次请求的执行轨迹**」组织：对话不再是左右气泡，而是一条自上而下的时间轴，每条回答上方都挂着可展开的思考步骤、工具调用与检索来源。平台的四个核心页面是 **概览 / 对话 / 知识库 / 运行观测**。

## 环境准备

### Node 版本

需要 **Node.js ≥ 18**（Vite 6 的硬性要求）。推荐 20 LTS 或更高。

```bash
node -v    # 应为 v18.x / v20.x / v22.x
npm -v
```

> 本项目在 Node **v22.23.2** / npm **10.9.8** 下完成构建验证。若 `node -v` 低于 18，请先升级。

### 安装依赖

```bash
cd CogAgent-frontend
npm install
```

依赖刻意保持精简，只有 6 个运行时依赖：

| 依赖 | 用途 |
| --- | --- |
| `vue` / `vue-router` / `pinia` | 框架、路由、状态管理 |
| `axios` | HTTP 客户端，统一解包后端的 `Result<T>` 结构 |
| `marked` | 渲染模型返回的 Markdown |
| `dompurify` | 消毒 Markdown 产物，防止模型输出里的脚本注入页面 |

**没有引入任何 UI 组件库**，样式全部自研，原因见「设计说明」。

### 后端准备

前端只负责展示，真正的 Agent 能力在后端。启动前端之前，请先确认：

1. **CogAgent 后端已在 8080 端口运行**（`CogAgent-app` 的启动类）。
2. 后端依赖的中间件可用：**MySQL、Redis、Milvus**。其中 **Redis 是必选**——短期记忆直接依赖它，不通会导致对话报错。
3. 环境变量已配置：`DEEPSEEK_API_KEY`（对话模型）、DashScope 的 Embedding Key。

只想起前端看看界面、暂时不接后端也是可以的，见[测试步骤 T0](#t0-无后端时的降级表现)。

## 启动

### 开发模式（日常使用这个）

```bash
cd CogAgent-frontend
npm run dev
```

启动后访问 **http://localhost:5173**（默认端口，被占用时会自动换到 5174 等）。

开发服务器已配置代理：所有 `/api` 开头的请求自动转发到 `http://localhost:8080`。

如果后端不在本机或不在此端口，改 `.env.development`：

```ini
VITE_PROXY_TARGET=http://192.168.1.100:8080
```

**改完必须重启开发服务器**，Vite 的代理配置不会热更新。

### 生产构建

```bash
npm run build      # 产物输出到 dist/
npm run preview    # 本地预览构建产物，默认 http://localhost:4173
```

## 跨域说明

后端 `CogAgent-trigger` 目前**没有配置任何 CORS 策略**（全仓库没有任何 `@CrossOrigin`、`CorsConfiguration` 或 `addCorsMappings`），浏览器直连 8080 会被同源策略拦截。

本项目的应对方式：

- **开发期**：走 Vite 的 `devServer.proxy`（见 [vite.config.js](vite.config.js)）。浏览器视角下所有请求都发往 `localhost:5173`，同源，不产生跨域。**这是开发期唯一需要做的事，无需改后端。**
- **生产期（推荐）**：把 `dist/` 交给 Nginx，与后端同域部署，用 Nginx 反代 `/api` 到 8080。同样不涉及跨域。

```
location / {
    root /usr/share/nginx/html;
    try_files $uri $uri/ /index.html;
}
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_buffering off;          # 流式对话必须关掉缓冲，否则 SSE 会被攒着一次性吐出
    proxy_read_timeout 300s;
}
```

- **生产期（前后端分域）**：在 `.env.production` 里设置 `VITE_API_BASE_URL=https://你的后端域名`，**同时必须由后端补齐 CORS 响应头**，否则浏览器会拦下请求。后端加一个全局配置即可：

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("*")   // 生产环境请改成前端的具体域名
                .allowedMethods("GET", "POST", "OPTIONS")
                .allowedHeaders("*")
                .maxAge(3600);
    }
}
```

> **流式接口的额外注意**：`/api/v1/chat/stream` 是 SSE。若经由 Nginx 转发，务必加 `proxy_buffering off;`，否则响应会被缓冲，界面上表现为「等很久，然后一次性全部出现」，而不是逐字输出。

### 设计说明

界面走的是「工程控制台」的路子，刻意避开模板化的观感，几个具体决定：

- **配色**：微冷的中性纸灰打底，青瓷墨绿作唯一强调色，赭黄只用于「进行中/降级」，铁锈红只用于失败。没有渐变、没有彩色卡片、没有投影堆叠——分区全部由 1px 发丝线和留白承担。
- **字体**：中文走系统字体栈（苹方 / 微软雅黑 / 思源黑体），数字与 ID 一律等宽并启用 `tabular-nums`，保证纵向对齐。**刻意不引 Google Fonts**——国内网络不可达，会导致首屏字体闪烁。
- **结构**：消息流是一条贯穿的时间轴，执行轨迹是另一条垂直轴线。日期、编号这类标记只在它确实是**序列**时才出现，不做装饰性编号。
- **动效**：只有两处，都服务于状态表达——流式生成时的光标闪烁，和运行中节点的呼吸。没有全页入场动画，没有 hover 位移。

## 接口对照

| 前端调用 | 后端接口 | 说明 |
| --- | --- | --- |
| `sendChat()` | `POST /api/v1/chat` | 同步对话。返回 `reply` + `thinkingSteps` + `usedTools` + `sources` + `tokenUsage` + `traceId` |
| `streamChat()` | `POST /api/v1/chat/stream` | SSE 流式。**注意语义差异，见下** |
| `uploadDocument()` | `POST /api/v1/documents/upload` | 文档上传，同步完成解析→切片→向量化→入库 |
| `probeBackend()` | `POST /api/v1/chat`（空 message） | 连通性探测，见下 |

### 三个必须知道的接口细节

**1. `mode` 字段传的是大写枚举名，不是小写 code**

后端 `ChatRequest.mode` 是 Java 枚举 `AgentMode`，Spring 默认按枚举的 `name()` 反序列化，所以前端必须传 `REACT` / `PLANNER` / `REFLECTION` / `DIRECT`。传 `react` 这类小写 `code` 会得到 HTTP 400。

映射集中定义在 [src/constants/agent.js](src/constants/agent.js)。若后端日后给 `AgentMode` 加上 `@JsonCreator` 改走 `fromCode()`，只改那一个文件的 `value` 即可。

**2. 「自动路由」= 请求体不带 `mode` 字段**

`AgentMode` 上的 `@Builder.Default` 只对 Lombok 构建器生效，Jackson 反序列化时 `mode` 为 `null` 才会触发 `IntentRecognizer` 路由。所以「自动路由」模式下前端**完全不发送该字段**，而不是发一个空串。

**3. 流式接口不经过 Agent 编排**

`/api/v1/chat/stream` 走的是 `AgentOrchestrator.chatStream()`，它直接调用 `buildDirectPrompt` + `modelRouter.stream()`，**绕过了 ReAct / Planner / Reflection**。因此：

- 它**不会**返回思考步骤、工具调用、检索来源，也**不会**应用你选的 Agent 模式；
- 它只是一条带记忆上下文的纯文本流。

界面上因此把流式明确标注为「直通流式」，并且不显示轨迹面板——不假装它有执行过程。**需要看思考过程时请关掉流式开关。**

### 关于连通性探测

探测方式是一条**注定被参数校验拦下**的对话请求：

```
POST /api/v1/chat   { "message": "" }
→ Bean Validation 失败 → GlobalExceptionHandler → HTTP 400
→ message: "message: 消息内容不能为空"
```

选它的三个理由：**零副作用**（校验发生在 AgentOrchestrator 之前，不写记忆、不调模型、不产生费用）、**不可伪造**（这条中文文案只有本后端会产生，能确认打到的是 CogAgent 而不是别的服务）、**链路完整**（路由注册、Jackson、校验、全局异常处理、`Result` 包装一次性全走通）。

## 人工测试步骤

以下步骤假定：前端已启动在 **http://localhost:5173**。

### T0 无后端时的降级表现

**先故意不启动后端**，用来验证错误提示是否说人话。

| 步骤 | 预期结果 |
| --- | --- |
| 1. 打开 http://localhost:5173 | 概览页正常渲染，无白屏 |
| 2. 看右上角状态徽标 | 显示红点 + **「未连接」** |
| 3. 点击徽标 | 弹出面板，写明探测方式、预期响应、以及「连接不上后端服务…」，并提示检查 8080 端口与 `vite.config.js` 的 proxy |
| 4. 进入「对话」页，随便发一条消息 | 助手消息位置出现红色错误块，文案为「连接不上后端服务（请求未送达）…」，并给出「检查后端是否已在 8080 端口启动」的指引。**不应**显示「服务内部错误」这类误导性文案 |

> 这一步专门验证一个易错点：后端没启动时，Vite 代理返回的是 HTTP 500 + `text/plain` 空响应体。如果直接按状态码报错，就会把「忘了起后端」说成「后端 500 错误」，把排查方向带偏。前端通过「5xx 且响应体不是 `Result` 结构」来判别请求是否真的送达。

**现在启动后端**，继续下面的测试。

## 常见问题排查

### 1. 页面能打开，但右上角一直显示「未连接」

按顺序检查：

1. **后端真的在跑吗？** 浏览器直接访问 http://localhost:8080/api/v1/chat —— 如果返回一个 JSON 错误（哪怕 404/405），说明端口有服务。
2. **端口对不对？** 后端 `application.yml` 里是 `server.port: 8080`，`context-path` 是 `/`。若你改过端口，同步改 `.env.development` 的 `VITE_PROXY_TARGET`。
3. **改完 .env 重启了吗？** Vite 的代理配置在启动时读取，**不会热更新**。必须 `Ctrl+C` 后重新 `npm run dev`。
4. **是不是有别的服务占了 8080？** 徽标显示「响应异常」（赭黄色）而不是「未连接」，就属于这种情况——端口上有东西在监听，但它返回的不是 CogAgent 的响应。点开徽标能看到实际拿到的状态码和文案。

### 2. 发消息报 `400`，提示「请求参数校验失败」或 JSON 解析错误

最可能是 `mode` 字段的取值不对。后端 `AgentMode` 是 Java 枚举，**必须传大写枚举名**（`REACT` / `PLANNER` / `REFLECTION` / `DIRECT`），传小写 `react` 会反序列化失败。

前端已在 [src/constants/agent.js](src/constants/agent.js) 里做归一，正常操作不会出问题。如果你是手工用 curl / Postman 测的，请确认这点。

### 3. 流式输出「等很久然后一次性全出来」

**先确认这是不是真的故障**：如果后端本身就慢（ReAct 多轮调用），第一次 token 出现前确实要等。真正的缓冲问题表现为：全程无输出，最后一瞬间全部出现。

排查方向：

- **是不是经过了 Nginx？** 加 `proxy_buffering off;`（见[跨域说明](#跨域说明)）。
- **浏览器开发者工具**：Network 面板找到 `stream` 请求 → 看 Response 是否在逐步增长。逐步增长说明前端没问题，是上游在缓冲。
- **检查你是不是开着代理软件**：某些企业代理会缓冲 `text/event-stream`。

### 4. 回答能出来，但「检索来源」永远是空的

这是**最常见也最容易误判**的问题，按顺序排查：

1. **知识库里到底有没有东西？** 「上传记录」表是**本地**的，换台电脑或清了 localStorage 就是空的，但不代表 Milvus 里没数据。反过来，表里有记录也不代表向量真的入库成功了——请看上传时的状态是否为成功。
2. **意图有没有触发检索？** 后端逻辑是 `if (request.isEnableRag() && intent.isNeedsRag())`，**两个条件都要满足**。闲聊类问题不会触发检索，这是设计如此。换一个明确的知识型问题再试。
3. **相似度阈值**：`agent.rag.similarity-threshold` 默认 `0.5`，低于阈值的结果会被过滤掉。如果文档内容和问题措辞差得远，可能全部被过滤。
4. **精排之后可能被截断**：`rerank-top-n` 默认 3，候选超过阈值时只保留精排后的前 3 条。
5. **Milvus 真的连上了吗？** 看后端启动日志里 `工具注册中心初始化完成` 附近的 Milvus 连接信息。
6. **Embedding 服务可用吗？** 切片和查询都要走 DashScope 的 `text-embedding-v3`。如果 Embedding Key 没配，写入和检索都会静默失败。

### 5. 上传文档失败

| 提示 | 原因与处理 |
| --- | --- |
| 「暂不支持 .x 格式」 | 前端本地拦截，未发请求。换 PDF / DOCX / TXT / MD / HTML |
| 「超出后端 50MB 的单文件上限」 | 前端本地拦截。压缩文件或拆分 |
| 「上传文件大小超出限制」 | 后端返回，可能是请求总大小超了 `max-request-size`（100MB） |
| 「文档处理失败: ...」 | 后端 ETL 抛错。重点检查 Milvus 与 Embedding 服务；加密 PDF 也需要先解密 |
| 卡在「处理中」很久 | 大文档的向量化本身就慢。后端是同步接口，中途不推送进度，只能等。超时上限设的是 5 分钟 |

### 6. 改了代码不生效

- 确认开发服务器还在运行，看终端有没有编译报错。
- 改了 `.env.*` 或 `vite.config.js`：**必须重启**。
- 改了 `src/constants/agent.js` 里的枚举值：可能需要硬刷新（`Ctrl + Shift + R`）。
- 界面状态诡异（比如模式选不中）：清一下 localStorage —— 开发者工具 → Application → Local Storage → 删除 `cogagent.*` 开头的键，刷新。

### 7. `npm install` 很慢或失败

```bash
# 换国内镜像
npm config set registry https://registry.npmmirror.com

# 或者删除残留后重来
Remove-Item -Recurse -Force node_modules
Remove-Item package-lock.json
npm install
```

## 已知边界

这些是后端能力所限，前端做了如实呈现而非掩盖，测试时请勿当成 bug：

| 现象 | 原因 |
| --- | --- |
| **换浏览器/换电脑后会话列表是空的** | 后端没有会话列表接口，会话存在 localStorage。但服务端记忆仍在——`conversationId` 是前端生成传给后端的 |
| **「运行观测」的数据不是服务端全量流量** | 后端 `TraceService` 只写日志，没有查询接口。全部指标由前端采集，上限 300 条 |
| **「所选模式分布」用的是你的选择，不是后端实际判定** | `ChatResponse` 没有 `mode` 字段，自动路由时后端选中了哪个模式不会返回。界面已明确标注 |
| **流式模式下看不到执行轨迹** | `/chat/stream` 绕过 Agent 编排，是直通模型的纯文本流 |
| **上传记录表里的「大小」「上传时间」是前端补记的** | `DocumentUploadResponse` 只返回 documentId / fileName / chunkCount / status / processingTimeMs |
| **ETL 四阶段没有分段进度** | 上传接口是同步的，中途不推送进度。界面只显示真实总计时间，四阶段在处理完成后一起落定 |
| **「移除」上传记录不会删除 Milvus 里的向量** | 没有对应的删除接口。界面和提示文案都已说明 |
| **运行参数里没有 temperature / maxTokens** | 后端 DTO 定义了这两个字段但从未消费（只有 `modelOptions.model` 被读取），放了滑块反而是误导 |
| **工具至少保留一项** | 后端把 `tools` 为空视为「使用全部工具」，没有「禁用全部」的表达方式 |

## 技术栈

| | |
| --- | --- |
| 框架 | Vue 3.5（`<script setup>` 组合式 API） |
| 构建 | Vite 6 |
| 路由 | Vue Router 4（hash 模式，静态托管无需服务端重写） |
| 状态 | Pinia 2（setup 语法） |
| HTTP | axios 1.x |
| Markdown | marked 15 + DOMPurify 3 |
| 样式 | 原生 CSS + 自定义属性（设计令牌） |

**为什么用 hash 路由**：前端是纯静态产物，hash 模式不需要后端配置 fallback 重写，`dist/` 丢给任意静态服务器都能直接跑，少一类部署问题。
